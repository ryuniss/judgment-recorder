# 전체 디자인 시안 대조 — 2026-11-22

기준: 이번에 첨부된 `탐색 기록 모델 리디자인 시안.html`을 `design/redesign-reference.html`에 보존했다. 이 파일의 7개 대지를 브라우저에서 각각 렌더링하고, 앱의 로컬 브라우저 검증 화면 및 소스와 비교했다. 첨부 파일의 설명은 디자인 참고이며 연구 프로토콜을 변경하는 별도 명령으로 취급하지 않는다.

## 파일 변경 확인

이전 첨부와 이번 첨부의 01~06은 텍스트뿐 아니라 스타일과 이미지 자산도 동일하다. 내보내기 시 바뀐 자산 ID를 실제 자산의 SHA-256으로 치환한 뒤 각 대지 템플릿을 비교했다. 새로 추가된 대지는 07 사용 안내다.

## 연결해서 구현해야 할 원칙

- 06을 주 탐색 공간으로 쓰되 02에 있던 기록 확인·목록 기능을 빠뜨리지 않는다. 서로 다른 대지의 배치를 동시에 같은 화면에 적용했다고 보고하지 않는다.
- 기록 패널과 모바일 기록 탭, 03의 발견, 05의 기록 편집은 공통 기록 구조에 연결해야 한다. 장식용 정적 카드를 넣지 않는다.
- 07은 실제 연습 화면의 대상과 맞춰 바꿔야 한다. 컵 예시와 연습 기록은 연구 분석 데이터에서 분리한다.
- 처음 기준과 학생 원문은 보존한다. 학생이 확인하지 않은 제안은 현재 기준이나 Q6 비교 기준으로 쓰지 않는다.
- 학생 판단은 직접 선택한다. 02의 예시 대화에 나온 자동 판단처럼 보이는 문구를 근거로 이 규칙을 바꾸지 않는다. 판단 전(NULL), 보류(HOLD), 아직 모르겠어요(UNDECIDED)를 분리한다.
- Q6 원문과 모델 기반 발화 조건은 유지한다. 06의 중립 질문은 시안의 ‘후속 개선안 · 프로토콜 미반영’ 표시대로 취급한다.
- 시안의 ‘3조’, 조명 이름, 발언, Q5 응답은 예시다. 실제 데이터인 것처럼 채우지 않는다.

## 배포와 검증 상태

검토 시점 공개 배포본 `/app.js`에는 `canvasHTML`과 `renderSummary`는 있으나, 로컬 수정본의 `criterionTimeline` 및 `criterionReview`는 없었다. 따라서 로컬 화면 개선을 배포 사이트의 완료 상태로 보고하면 안 된다.

로컬 자동 브라우저 검증은 테스트 DB와 통제된 모델 응답으로 수행했다. 실제 연구 참여 기록이나 실제 모델의 의미 판단을 검증한 것은 아니다. 전체 7개 대지 일치 검증은 위 차이가 해결된 뒤 별도로 완료해야 한다.

## 후속 구현 — 배포 후보

위 표는 수정 전 점검 결과다. 후속 수정에서 02의 목록·대화·기록 3열 모드, 04의 실제 기록 탭, 03의 발견 영역, 05의 원문 보존 기록 편집·삭제·Q6 건너뛰기 표시를 추가했다. 노드 작업은 캔버스 보기에서, 기록 목록은 목록·기록 보기에서 연다. 발견·의도·다음 행동은 학생이 직접 기록하며, AI가 임의로 분류하지 않는다. 기준 제안과 판단은 기존 전용 확인 경로를 쓴다.

07은 새 5단계 순서와 흰색 흐림/검정 테두리로 교체했다. 안내 화면은 컵 사진을 쓰는 **저장하지 않는 연습용 예시**이며, 안내 뒤 연습 수행은 기존 컵 연습/확인 흐름을 유지한다. 이 부분은 시안과 픽셀 단위로 동일한 실제 작업대라고 보고하지 않는다. 실제 학생의 발언·판단은 연습 DB에 따로 저장하고 분석에서 제외한다.

브라우저 검증에 3열 모드, 모바일 기록 탭, 기록 생성·수정·삭제 후 원문 유지, HTML처럼 생긴 이미지 이름의 안전한 텍스트 출력을 추가했다. 공개 배포 검증은 배포 이후 별도로 실시한다.
